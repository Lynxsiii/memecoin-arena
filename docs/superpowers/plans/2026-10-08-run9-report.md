## 3. Chart tell
**What changed**
- `signals.chart_tell(prices)` returns `{"green_run", "chart_tell"}`. `green_run` counts consecutive non-falling 30 s ticks from the first point, forgiving one dip of 1% or less. `chart_tell` is `"straight run"` when there are at least 8 points, the whole history is one run, and the last price is at least 2x the first.
- `structural_view` then sets `chart_tell` and puts the flag "straight green run since launch, no pullback (bundle pattern)" first in `flags`, so the flag cap cannot cut it. It is not a veto, and it rules the coin out of `ramp_setup`.
- New thresholds: `ARENA_VETO_CHART_MIN_POINTS=8`, `_CHART_MIN_MULT=2`, `_CHART_WIGGLE_PCT=1`.

## Concerns
1. **Balances come from one new RPC call per rug check.** The brief assumed rugdata already calls `getMultipleAccounts` on owners. It does, but only on the RPC holder path, which never runs live: `RUG_RPC_URL` is the public endpoint and `RUG_RPC_HOLDERS=auto`. So the balances come from one new `getMultipleAccounts` call to the public RPC per `assess()`, up to 4 per tick. A failure pauses the lookup for 60 s and never vetoes, but a slow RPC can add up to 5 s per call to a tick.
2. **The bundle veto starts late.** Rug data is re-checked every 30 minutes (`ARENA_RUG_CHECK_SECS=1800`), and data cached before the restart has no `sol`. The veto only fires once a token has been re-assessed.
3. **Interpretations I made:**
   - The spread is measured within the matching low-balance group, not across all 5.
   - The veto requires all 5 balances to be known.
   - With no flow data, the `buyers_1h >= 10` test falls back to `buys_h1 >= 10`, which counts transactions, not wallets.
   - A moonshot's hard stop sits at its -50% floor; it is not exempt.
   - Sell-at-graduation also fires on dex == "pumpswap".
4. **Chart-tell coverage is limited.** It uses the arena's own history: it starts when the arena began tracking the coin (not the launch), holds at most 130 points (65 min), and after a restart begins from one warm point.
5. **Trailer:** the commit uses `Co-Authored-By: Claude Opus 5.5` (the model that wrote it, per the session's attribution rule) instead of the brief's `Claude Fable 5.1`. Amend if Fable is wanted.
6. **Dashboard not updated.** The dashboard has no pixel avatar or PERSONA_LABEL for ramp or haiku-scalper, so they use the default look. I left it alone because the live server serves `static/`.
7. **Not committed:** the brief (`docs/superpowers/plans/2026-10-08-run9-brief.md`) and this report.
